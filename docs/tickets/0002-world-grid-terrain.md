# 0002 — World grid & terrain rendering

- **Status:** ready
- **Milestone:** M1 — World Foundation
- **Depends on:** 0001

## Goal
A tile-grid world exists and renders: a bounded map made of terrain tiles (e.g. grass, forest, water, rock) that later tickets can place buildings on and path settlers across.

## Context
Art direction is decided: 2D, top-down, tile-grid based (`docs/roadmap.md`). Godot's `TileMap`/`TileSet` is the natural fit. For this first ticket, terrain content can be hand-authored or trivially randomized — procedural generation is explicitly deferred (see roadmap "Later/stretch").

## Scope
- Define a `TileSet` with at least: grass (buildable), forest (contains a wood resource, see 0004/0009), water (impassable, non-buildable), rock/stone outcrop (impassable, harvestable later).
- Build one fixed-size map (e.g. 64x64 or similar) via a `TileMap`, either hand-painted in the editor or generated by a simple deterministic placeholder algorithm (noise-based is fine, but not required to be "final" generation).
- Expose a basic grid query API (script/autoload) other systems can use: tile at world position, tile walkability, tile buildability, world-to-grid and grid-to-world coordinate conversion.
- Mark map boundaries so the camera (0003) and pathfinding (0006) can clamp/respect them.

## Out of scope
- Procedural/infinite terrain generation.
- Multiple biomes.
- Terrain that changes at runtime (e.g. chopped forest tile reverting to grass) — that's owned by the building/resource tickets that consume terrain (0009), this ticket only needs to expose the query API they'll use.

## Acceptance criteria
- [ ] A `TileSet` with the listed terrain types exists and renders correctly in the editor and at runtime.
- [ ] A single map scene loads and displays a mix of all terrain types.
- [ ] A script/autoload exposes: `is_walkable(grid_pos)`, `is_buildable(grid_pos)`, `world_to_grid(world_pos)`, `grid_to_world(grid_pos)`, and map bounds.
- [ ] Walkability/buildability rules are correct per tile type (water impassable, rock impassable+unbuildable, grass/forest buildable where sensible).

## Open questions
- Map size for the MVP — pick something small enough to iterate fast (e.g. 48x48–64x64) and revisit once performance/scale matters.
- Whether forest tiles are single-tile resource nodes or whether trees are separate objects placed on top of grass tiles (affects 0009's harvesting model) — recommend deciding in 0009 rather than here, but the terrain API should not preclude either.
